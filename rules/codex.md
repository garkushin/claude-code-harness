# Codex как сабагент

Codex — исполнитель наравне с `developer-middle` и `developer-senior` (в том числе на задаче с меткой `L`) и рецензент. Выбор делает оркестратор, когда пишет бриф; в колонку исполнителя `progress.md` пишется `codex`. Бриф, приёмка и решения остаются за оркестратором. Брак не переспрашивается: задача уходит `developer-senior`.

Вызов — только агентом `codex:codex-rescue` (`subagent_type`). Скилл и команду `codex:rescue` в оркестрации не использовать; `codex-companion.mjs` напрямую не вызывает никто. Companion отвечает «not installed» или «missing runtime support» — пользователь запускает `/codex:setup`, работу пока делает роль Claude.

## Модель

Forwarder сам `--model` и `--effort` не ставит: указывай их в промпте явно. Модель — по frontmatter роли Claude, которую Codex заменяет: `opus` → `gpt-6.1-sol`, `sonnet` → `gpt-6-luna`. `--effort` — из `effort` той же роли; плагин принимает значения до `xhigh` включительно. На ревью Codex заменяет `reviewer-middle`, а если задача задевает конкурентность, деньги, данные или безопасность — `reviewer-senior`; дополнительное ревью на L — по `reviewer-senior`.

## Когда отдавать

Задачи плана с кодом и тестами, правки по точному списку — да. MCP: Codex получает только серверы из своего конфига с `default_tools_approval_mode = "approve"` и только при запуске с `--write`; плагин запускает его с политикой одобрений `never`, остальные вызовы отклоняются, без `--write` MCP недоступны совсем. Задачи с другими MCP (`corporate` — Jira, Confluence, Grafana), запись в `.git`, push и публикация — только ролям Claude.

## Подготовка и коммит

Подготовку и закрытие задачи Codex делает `developer-middle` по брифу. До запуска: worktree от ветки задачи в `.claude/worktrees/`, restore, `pub get`, `fetch`. После: коммит — дифф в границах задачи, `git add` поимённо, без служебных файлов Codex. Worktree и исполнитель записываются в `progress.md`, worktree удаляет бриф слияния. Codex не коммитит: `.git` в его песочнице закрыт на запись.

После задачи проверь `git status --short` основного checkout и worktree активных потоков из `progress.md`: изменения вне своего worktree — брак. Песочница блокирует шаг, о котором пользователь ещё не решал, — не обходи, спроси пользователя.

## Запуск и ожидание

В промпте forwarder'у: `--fresh --cwd <worktree>`, бриф — файлом с абсолютным путём, текст передать без изменений. Каждая новая задача — `--fresh`. Ревью и правки по списку — с `--wait`. Задача плана с тестами — с `--background`, итог приходит по уведомлению: бери его из `tasks/<id>.output` сессии (`<id>` — номер фоновой задачи Claude Code), итог — строки без префикса `[codex]`.

Пока задача Codex идёт, сессию не завершай и `/clear` не делай: хук плагина на SessionEnd останавливает задачи Codex. Запущенная задача — строкой в `progress.md`. Задача упала на окружении (сеть, restore, песочница) — после исправления окружения `SendMessage` тому же forwarder'у с `--resume --cwd <тот же каталог>`; брак результата — по правилу выше.

## Ревью

На M рецензент один: Codex или `reviewer-*`, выбор оркестратора пишется в `progress.md`; работу Codex на M ревьюит рецензент Claude. На L Codex — дополнительное направление к рецензентам Claude, не вместо них.

Бриф — как рецензенту M по `rules/review.md`: направления «соответствие задаче и спеке (включая корректность)» и «качество кода», Assessment по каждому; диапазон SHA коммитов потока, формат вердикта из шаблона `superpowers:requesting-code-review`. Запуск: `--wait`, без `--write`, `--cwd <worktree потока>`. На L — направление из брифа L, диапазон SHA ветки задачи, `--cwd <основной checkout>`; остальное — как на M. Находку, которой нужен эксперимент, Codex помечает непроверенной; её сверяет роль при разборе (`receiving-code-review`) или `reviewer-*` по брифу в своём worktree.

Перепроверка правок — `SendMessage` тому же forwarder'у с `--resume --cwd <тот же каталог>`, только если после ревью в этом каталоге не запускалась другая задача Codex; иначе `--fresh` с файлом находок и диапазоном SHA правок. Брак ревью Codex уходит `reviewer-senior`; брак задачи — `developer-senior`.

## Промпт

Первая строка промпта: «Ты сабагент-исполнитель по брифу, не оркестратор; сабагентов не запускай». Промпт самодостаточный: Codex не видит разговор. Абсолютные пути к worktree, брифу и спеке; файлы параллельных потоков — «не трогать». Запреты: push, публикация, коммит, служебные файлы в worktree (логи — в `/private/tmp`). Структура — по скиллу `codex:gpt-5-4-prompting`, рецепт по типу задачи.

Задача с `--write` пишет подробности в файл по пути из брифа и отвечает не больше 10 строк. Ревью только на чтение возвращает вердикт в ответе, оркестратор сохраняет его в `reviews/`.
