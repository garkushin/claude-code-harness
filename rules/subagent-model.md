# Выбор сабагента

Сабагента выбирает оркестратор при запуске — по роли, через `subagent_type`. Роли с суффиксом `-middle`/`-senior` — один и тот же исполнитель двух тиров: `-middle`, когда решения приняты и цена ошибки невысока, `-senior` — когда задача требует своих решений или ошибка дорогая. Модель и effort зашиты в определение роли: параметр `model` при вызове меняет только модель, effort остаётся из определения.

- `analyst` — что есть сейчас: код проекта, требования, данные, текущее поведение.
- `researcher` — как устроены чужие системы: библиотеки, пакеты, фреймворки, внешние API; отладка без воспроизведения.
- `architect` — варианты и выбор, спека, план с потоками, архитектурное ревью. Дорогой: не для реализации и рутинного ревью.
- `developer-middle` — реализация, где решения приняты: план с готовым кодом, правки по списку, исправления по ревью, интеграция потоков без сложных конфликтов.
- `developer-senior` — реализация со сложностью: свои решения внутри задачи, конкурентность, деньги, данные, отладка с воспроизведением, конфликтная интеграция.
- `verifier-middle` — проверка запуском по готовому чек-листу; `verifier-senior` — когда сценарий надо собрать самому: сервис и зависимости, интеграционные и e2e-сценарии.
- `reviewer-middle` — ревью по направлению с невысокой ценой ошибки: спека, тесты, консистентность; `reviewer-senior` — корректность, конкурентность, безопасность, деньги, данные, производительность.
- `tech-writer` — текстовая документация, описание MR.
- Скилл велит диспатчить `general-purpose` (superpowers и другие) — подставляй роль по тем же признакам; промпт из скилла не меняй.
- Ни одна роль не подошла — `general-purpose`: модель и effort сессии.

Сабагент вернул брак — не переспрашивай его: перезапусти на тир выше (`-middle` → `-senior`) или с исправленным брифом.
