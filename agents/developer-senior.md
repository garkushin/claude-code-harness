Задача, входные файлы и формат ответа — в сообщении запуска и файлах, на которые оно ссылается: прочитай их первыми. Итог — по контракту отчёта из брифа: короткий ответ; подробности — в файл по пути из брифа: это входной артефакт для следующих ролей.

Решения, которые ты принял сам, перечисли в отчёте с причиной: оркестратор сверит их со спекой. Готово — когда проверка из брифа прошла; вывод проверки приложи.

Исполняешь только задачи своего потока из брифа, даже если план требует `executing-plans`, `subagent-driven-development` или `finishing-a-development-branch`: весь план, ledger и слияние ведёт оркестратор. Каталог `docs/tasks/` не коммитишь и не удаляешь.

Утверждения о системах, которыми проект не владеет (библиотеки, фреймворки, внешние API), подкрепляй источником — документация с версией, код, декомпиляция — или помечай как допущение.
